# Проектирование сервиса каталога шабонов ('design.md')

## 1. Описание сервиса, то как мы сами это видим

Сервис предназначен для хранения шаблонов документов в форматах '.odt' и '.ott' также ведение их неизменяемой истории версий. 

** Основные принципы работы: **
1. Каждый шаблон имеет постоянный строковый идентификатор `template_id` (например, `notice`), который не зависит от имени загружаемого файла.
2. При каждой успешной загрузке файла сервис вызывает модуль `template_parser.py`, извлекающий текст документа, список подстановочных полей (например, `{NAME}`, `{DATE}`), формат, размер и контрольную сумму SHA-256.
3. Бинарные файлы сохраняются в файловом хранилище сервиса, а метаданные шаблонов, история версий и пути к файлам записываются в PostgreSQL.
4. Версии нумеруются последовательно (`1.0`, `1.1`, ..., `1.9`, `1.10`) и являются неизменяемыми (immutable): загрузка новой редакции не затирает предыдущие версии и их файлы, а при ошибке разбора файла новая версия не создаётся.


## 2. Модель данных и проектирование БД

Схема базы данных спроектирована в третьей нормальной форме (3НФ) и состоит из двух таблиц со связью `1 : 1..N` (у каждого шаблона существует минимум одна версия, создаваемая в момент первой загрузки).

Посмотреть на схемы можно в папке (ВЫПОЛНЕНИЕ ТЗ). Прикреплено два файла в формате draw.io и соответственно в .png.


### 2.1. Таблица `templates`
** Для чего:** Она хранит постоянную карточку шаблона (его уникальный идентификатор каталоге и дату первичной регистрации).

| Поле | Тип PostgreSQL | Обязательность | Ограничения и значения по умолчанию | Описание |
| :--- | :--- | :--- | :--- | :--- |
| `template_id` | `text` | `NOT NULL` (через `PK`) | `PRIMARY KEY` | Постоянный строковый идентификатор шаблона (например, `notice`) |
| `created_at` | `timestamptz` | `NOT NULL` | `DEFAULT current_timestamp` | Дата и время создания шаблона в UTC |

* **Первичный ключ:** `PRIMARY KEY (template_id)` — определяет шаблон в каталоге.
* **Внешние ключи:** отсутствуют.
* **Ограничения уникальности:** уникальность `template_id` обеспечивается первичным ключом.


### 2.2. Таблица `template_versions`
** Для чего:** Хранит неизменяемую историю версий каждого шаблона, метаданные загруженного файла, ссылку на файл в хранилище и результаты разбора из `template_parser.py`.

| Поле | Тип PostgreSQL | Обязательность | Ограничения и значения по умолчанию | Описание |
| :--- | :--- | :--- | :--- | :--- |
| `template_id` | `text` | `NOT NULL` (через `PK`) | `PRIMARY KEY` | Постоянный строковый идентификатор шаблона (например, `notice`) |
| `created_at` | `timestamptz` | `NOT NULL` | `DEFAULT current_timestamp` | Дата и время создания шаблона в UTC |

* **Первичный ключ:** `PRIMARY KEY (template_id)` — однозначно определяет шаблон в каталоге.
* **Внешние ключи:** отсутствуют.
* **Ограничения уникальности:** уникальность `template_id` обеспечивается первичным ключом.


### 2.2. Таблица `template_versions`
**Назначение:** Хранит неизменяемую историю версий каждого шаблона, метаданные загруженного файла, ссылку на файл в хранилище и результаты разбора из `template_parser.py`.

| Поле | Тип PostgreSQL | Обязательность | Ограничения и значения по умолчанию | Описание |
| :--- | :--- | :--- | :--- | :--- |
| `template_id` | `text` | `NOT NULL` (через `PK`) | `PK`, `FK -> templates(template_id)` | Идентификатор шаблона, к которому относится версия |
| `minor_version` | `int` | `NOT NULL` (через `PK`) | `PK`, `CHECK (minor_version >= 0)` | Целочисленный номер редакции (`0` для `1.0`, `1` для `1.1`, `10` для `1.10`) |
| `created_at` | `timestamptz` | `NOT NULL` | `DEFAULT current_timestamp` | Время сохранения данной версии в UTC |
| `title` | `text` | `NOT NULL` | — | Название шаблона на момент загрузки версии |
| `change_note` | `text` | `NULL` | — | Необязательный комментарий к изменениям |
| `file_name` | `text` | `NOT NULL` | — | Исходное имя загруженного файла (например, `Уведомление.ott`) |
| `file_format` | `varchar(3)` | `NOT NULL` | `CHECK (file_format IN ('odt', 'ott'))` | Формат файла, определённый парсером |
| `size_in_bytes` | `int` | `NOT NULL` | `CHECK (size_in_bytes BETWEEN 1 AND 20971520)` | Размер файла в байтах (не пустой, максимум 20 МиБ) |
| `file_sha256` | `varchar(64)` | `NOT NULL` | `CHECK (file_sha256 ~ '^[0-9A-Fa-f]{64}$')` | SHA-256 хеш содержимого файла (64 hex-символа) |
| `path_to_file` | `text` | `NOT NULL` | `UNIQUE` | Относительный путь к бинарному файлу в каталоге сервиса |
| `page_format` | `text` | `NOT NULL` | `DEFAULT 'A4'` | Формат страницы документа |
| `orientation` | `varchar(10)` | `NOT NULL` | `DEFAULT 'portrait'`, `CHECK (orientation IN ('portrait', 'landscape'))` | Ориентация страницы |
| `document_text` | `text` | `NOT NULL` | — | Полный извлечённый текст документа из парсера |
| `fields` | `jsonb` | `NOT NULL` | `DEFAULT '[]'::jsonb`, `CHECK (jsonb_typeof(fields) = 'array')` | JSON-массив описаний полей шаблона |

* **Первичный ключ:** составной ключ `PRIMARY KEY (template_id, minor_version)` — однозначно находит конкретную версию шаблона.
* **Внешние ключи:** `FOREIGN KEY (template_id) REFERENCES templates(template_id) ON DELETE RESTRICT` — связывает версию с родительским шаблоном и запрещает удаление шаблона, пока у него есть версии.
* **Ограничения уникальности:**
  1. `PRIMARY KEY (template_id, minor_version)` — исключает появление двух версий с одинаковым номером у одного шаблона.
  2. `UNIQUE (path_to_file)` — гарантирует, что разные версии никогда не перезапишут один и тот же файл на диске.
  

### 2.3. Индексы и их назначение

1. **`templates_pkey` (B-Tree по `templates.template_id`)** — создаётся автоматически для первичного ключа. Используется для быстрой проверки существования шаблона при `POST /api/v1/templates` и `GET /api/v1/templates/{template_id}`.
2. **`template_versions_pkey` (составной B-Tree по `template_versions(template_id, minor_version)`)** — создаётся автоматически для составного `PK`. Решает сразу три задачи:
   * точечный поиск версии по `template_id` и `minor_version`;
   * выборка истории всех версий шаблона по возрастанию или убыванию (`ORDER BY minor_version DESC`) без дополнительной сортировки в памяти;
   * быстрое нахождение актуальной версии (`MAX(minor_version)`).
3. **`template_versions_path_to_file_key` (уникальный B-Tree по `path_to_file`)** — создаётся автоматически для ограничения `UNIQUE`, гарантирует уникальность путей к файлам и не дает разным версиям шаблона ссылаться на один и тот же файл.
4. **`idx_templates_id_trgm` и `idx_template_versions_title_trgm` (GIN-индексы с `pg_trgm`)** — используются в `GET /api/v1/templates` для быстрого поиска по части строки без учета регистра (`ILIKE '%q%'`) по идентификатору шаблона и названию его актуальной версии.

## 3. REST API

Все маршруты начинаются с `/api/v1`. В примерах один шаблон `notice` имеет две версии, `1.0` и `1.1`. Обе загружены из файла с исходным именем `Уведомление.ott`. Размеры и контрольные суммы в примерах условные.

### 3.1. Загрузить шаблон или новую версию

`POST /api/v1/templates`

1. **Параметры.** Клиент передаёт файл и текстовые поля в теле `multipart/form-data`. Параметров пути и query нет.

   ```text
   Content-Type: multipart/form-data
   
   template_id = notice
   file = Уведомление.ott (содержимое файла)
   title = Уведомление
   ```

2. **Типы и ограничения.** Обязательны строковый `template_id` и `file`. Допустимы файлы `.ott` и `.odt` размером до 20 МиБ. `title`, `change_note`, `page_format` и `orientation` — необязательные строки. При первой загрузке без названия берём имя файла без расширения, при следующей — название предыдущей версии. Пропущенный комментарий сохраняется как `NULL`. По умолчанию формат страницы — `A4`, ориентация — `portrait`. Допустимые значения ориентации — `portrait` и `landscape`.
3. **Успех — `201 Created`.** Сервис назначает номер. У первой версии `minor_version = 0` в БД и `"version": "1.0"` в ответе. В ответе есть описание сохранённой версии и `saved: true`.

   ```json
   {
     "template_id": "notice",
     "version": "1.0",
     "title": "Уведомление",
     "kind": "simple",
     "created_at": "2026-11-14T09:00:00Z",
     "source_format": "ott",
     "checksum": "b94d27b9934d3e08a52e52d7da7dabfac484efe37a5380ee9088f7ace2efcde9",
     "size_bytes": 15643,
     "page": {
       "format": "A4",
       "orientation": "portrait"
     },
     "fields": [
       {
         "name": "Name",
         "type": "text",
         "required": true
       }
     ],
     "change_note": null,
     "saved": true
   }
   ```

4. **Ошибки.**

   | Статус | Когда возвращается | Пример ответа |
   |---|---|---|
   | `400 Bad Request` | Парсер не смог прочитать файл | `{"detail": "Не удалось прочитать файл"}` |
   | `413` | Файл больше 20 МиБ | `{"detail": "Размер файла превышает 20 МиБ"}` |
   | `422` | Отсутствует обязательное поле или неверный параметр формы, например `orientation=horizontal` | `{"detail": "Укажите orientation: portrait или landscape"}` |
   | `409 Conflict` | Две загрузки одновременно попытались создать версию с одним номером | `{"detail": "Версия 1.1 шаблона notice уже существует"}` |

5. **Работа с БД.** Сервис ищет `template_id` в `templates`. При первой успешной загрузке создаёт шаблон и запись с `minor_version = 0` в `template_versions`. При повторной загрузке берёт последний `minor_version` и добавляет новую запись с номером на единицу больше. Файл сохраняется отдельно, а в запись версии попадают его исходное имя, путь в хранилище и данные парсера. Если парсер отклонил файл, запись версии не создаётся.

### 3.2. Получить каталог шаблонов

`GET /api/v1/templates?q=notice&limit=20&offset=0`

1. **Параметры.** `q`, `limit` и `offset` передаются после `?`. Параметров пути и тела запроса нет.
2. **Типы и ограничения.** Все три параметра необязательны. `q` — строка для поиска по части идентификатора или названия актуальной версии без учёта регистра. Без `q` в выборку попадают все шаблоны. `limit` — целое от 1 до 100, по умолчанию 20. `offset` — целое от 0, по умолчанию 0. Сортируем по `template_id` по возрастанию.
3. **Успех — `200 OK`.** `total` — сколько шаблонов подошло под поиск до пагинации. `items` — список на текущей странице.

   ```json
   {
     "total": 1,
     "items": [
       {
         "template_id": "notice",
         "title": "Уведомление о собрании",
         "latest_version": "1.1",
         "versions_count": 2,
         "updated_at": "2026-11-14T10:00:00Z"
       }
     ]
   }
   ```

4. **Ошибка — `422`.** Например, для `limit=0` возвращается `{"detail": "limit должен быть от 1 до 100"}`. Если совпадений нет, возвращается `200 OK` с `{"total": 0, "items": []}`. Если `offset` пропустил все совпадения, список тоже пустой, а `total` сохраняет число совпадений.
5. **Работа с БД.** Сервис читает `templates` и `template_versions`. Для каждого шаблона берёт версию с наибольшим `minor_version`. Из неё берёт название, номер версии и время загрузки для `updated_at`. `versions_count` — число всех версий этого шаблона. После поиска сервис считает `total` и применяет `limit` и `offset` к отсортированному списку.

### 3.3. Получить карточку шаблона

`GET /api/v1/templates/notice`

1. **Параметры.** `template_id` передаётся в пути. Query-параметров и тела нет.
2. **Типы и ограничения.** `template_id` — обязательная строка. Адрес `/api/v1/templates` ведёт к каталогу.
3. **Успех — `200 OK`.** `versions` — список номеров версий от новой к старой. `descriptor` — описание актуальной версии.

   ```json
   {
     "template_id": "notice",
     "title": "Уведомление о собрании",
     "latest_version": "1.1",
     "versions": [
       "1.1",
       "1.0"
     ],
     "descriptor": {
       "template_id": "notice",
       "version": "1.1",
       "title": "Уведомление о собрании",
       "kind": "simple",
       "created_at": "2026-11-14T10:00:00Z",
       "source_format": "ott",
       "checksum": "2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824",
       "size_bytes": 17540,
       "page": {
         "format": "A4",
         "orientation": "landscape"
       },
       "fields": [
         {
           "name": "NAME",
           "type": "text",
           "required": true
         }
       ],
       "change_note": null
     }
   }
   ```

4. **Ошибка — `404 Not Found`.** Если шаблона нет, например `{"detail": "Шаблон unknown не найден"}`.
5. **Работа с БД.** Сервис проверяет наличие шаблона в `templates` и читает историю из `template_versions`. Версия с наибольшим `minor_version` даёт `title`, `latest_version` и данные для `descriptor`. Из всех записей собирается `versions`.

### 3.4. Получить описание конкретной версии

`GET /api/v1/templates/notice/versions/1.0`

1. **Параметры.** `template_id` и `version` передаются в пути. Query-параметров и тела нет.
2. **Типы и ограничения.** Оба параметра обязательны. `template_id` — строка. `version` — строка вида `1.N`, где `N` — неотрицательное целое число, например `1.0` или `1.10`.
3. **Успех — `200 OK`.** В теле возвращается описание выбранной версии. `kind` имеет значение `"simple"`, `page` — объект с параметрами страницы, `fields` — массив описаний полей. Даты передаются в UTC в формате ISO 8601.

   ```json
   {
     "template_id": "notice",
     "version": "1.0",
     "title": "Уведомление",
     "kind": "simple",
     "created_at": "2026-11-14T09:00:00Z",
     "source_format": "ott",
     "checksum": "b94d27b9934d3e08a52e52d7da7dabfac484efe37a5380ee9088f7ace2efcde9",
     "size_bytes": 15643,
     "page": {
       "format": "A4",
       "orientation": "portrait"
     },
     "fields": [
       {
         "name": "Name",
         "type": "text",
         "required": true
       }
     ],
     "change_note": null
   }
   ```

4. **Ошибки.**

   | Статус | Когда возвращается | Пример ответа |
   |---|---|---|
   | `404 Not Found` | Нет шаблона | `{"detail": "Шаблон unknown не найден"}` |
   | `404 Not Found` | Нет запрошенной версии | `{"detail": "Версия 1.5 шаблона notice не найдена"}` |
   | `422` | Неверный формат номера, например `1` | `{"detail": "Укажите версию в формате 1.N, например 1.0 или 1.1"}` |

5. **Работа с БД.** По `template_id` сервис проверяет наличие шаблона, затем ищет версию в `template_versions` по паре `(template_id, minor_version)`. Для `notice/versions/1.0` это `('notice', 0)`. Из `file_format`, `file_sha256` и `size_in_bytes` получаются `source_format`, `checksum` и `size_bytes`. `page_format` и `orientation` входят в объект `page`. `fields` и `change_note` берутся из записи версии.

### 3.5. Скачать файл конкретной версии

`GET /api/v1/templates/notice/versions/1.0/file`

1. **Параметры.** `template_id` и `version` передаются в пути. Сегмент `/file` указывает, что запрошен файл версии. Query-параметров и тела нет.
2. **Типы и ограничения.** Оба параметра обязательны. `template_id` — строковый идентификатор. `version` — строка вида `1.N`, как в запросе описания версии.
3. **Успех — `200 OK`.** В теле ответа идут байты файла. Тип берётся из сохранённого формата файла. В `Content-Disposition` параметр `filename` задаёт запасное имя на латинице, а `filename*` передаёт исходное имя в UTF-8.

   ```http
   HTTP/1.1 200 OK
   Content-Type: application/vnd.oasis.opendocument.text-template
   Content-Disposition: attachment; filename="uvedomlenie.ott"; filename*=UTF-8''%D0%A3%D0%B2%D0%B5%D0%B4%D0%BE%D0%BC%D0%BB%D0%B5%D0%BD%D0%B8%D0%B5.ott
   ```

4. **Ошибки.**

   | Статус | Когда возвращается | Пример ответа |
   |---|---|---|
   | `404 Not Found` | Нет шаблона | `{"detail": "Шаблон unknown не найден"}` |
   | `404 Not Found` | Нет запрошенной версии | `{"detail": "Версия 1.5 шаблона notice не найдена"}` |
   | `422` | Неверный формат номера, например `1` | `{"detail": "Укажите версию в формате 1.N, например 1.0 или 1.1"}` |

5. **Работа с БД.** Сервис проверяет наличие шаблона и находит нужную запись в `template_versions` по `(template_id, minor_version)`. По `path_to_file` открывает файл в хранилище, по `file_format` определяет `Content-Type` и берёт исходное имя из `file_name` для `Content-Disposition`.
