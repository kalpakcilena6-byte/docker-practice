# Проектирование сервиса каталога шабонов ('design.md')

## 1. Описание сервиса, то как мы сами это видим

Сервис предназначен для хранения шаблонов документов в форматах '.odt' и '.ott' также ведение их неизменяемой истории версий. 

** Основные принципы работы: **
1. Каждый шаблон имеет постоянный строковый идентификатор `template_id` (например, `notice`), который не зависит от имени загружаемого файла.
2. При каждой успешной загрузке файла сервис вызывает модуль `template_parser.py`, извлекающий текст документа, список подстановочных полей (например, `{NAME}`, `{DATE}`), формат, размер и контрольную сумму SHA-256.
3. Бинарные файлы сохраняются в файловом хранилище сервиса, а метаданные шаблонов, история версий и пути к файлам записываются в PostgreSQL.
4. Версии нумеруются последовательно (`1.0`, `1.1`, ..., `1.9`, `1.10`) и являются неизменяемыми (immutable): загрузка новой редакции не затирает предыдущие версии и их файлы, а при ошибке разбора файла новая версия не создаётся.


## 2. Модель данных и проектирование БД

Схема базы данных спроектирована в третьей нормальной форме (3НФ) и состоит из двух таблиц со связью `1 : 1..N` (у каждого шаблона существует минимум одна версия, создаваемая в момент первой загрузки).

Посмотреть на схемы можно в папке (ВЫПОЛНЕНИЕ ТЗ). Прикреплено два файла в формате draw.io и соответственно в .png.


### 2.1. Таблица `templates`
** Для чего:** Она хранит постоянную карточку шаблона (его уникальный идентификатор каталоге и дату первичной регистрации).

| Поле | Тип PostgreSQL | Обязательность | Ограничения и значения по умолчанию | Описание |
| :--- | :--- | :--- | :--- | :--- |
| `template_id` | `text` | `NOT NULL` (через `PK`) | `PRIMARY KEY` | Постоянный строковый идентификатор шаблона (например, `notice`) |
| `created_at` | `timestamptz` | `NOT NULL` | `DEFAULT current_timestamp` | Дата и время создания шаблона в UTC |

* **Первичный ключ:** `PRIMARY KEY (template_id)` — определяет шаблон в каталоге.
* **Внешние ключи:** отсутствуют.
* **Ограничения уникальности:** уникальность `template_id` обеспечивается первичным ключом.


### 2.2. Таблица `template_versions`
** Для чего:** Хранит неизменяемую историю версий каждого шаблона, метаданные загруженного файла, ссылку на файл в хранилище и результаты разбора из `template_parser.py`.

| Поле | Тип PostgreSQL | Обязательность | Ограничения и значения по умолчанию | Описание |
| :--- | :--- | :--- | :--- | :--- |
| `template_id` | `text` | `NOT NULL` (через `PK`) | `PRIMARY KEY` | Постоянный строковый идентификатор шаблона (например, `notice`) |
| `created_at` | `timestamptz` | `NOT NULL` | `DEFAULT current_timestamp` | Дата и время создания шаблона в UTC |

* **Первичный ключ:** `PRIMARY KEY (template_id)` — однозначно определяет шаблон в каталоге.
* **Внешние ключи:** отсутствуют.
* **Ограничения уникальности:** уникальность `template_id` обеспечивается первичным ключом.


### 2.2. Таблица `template_versions`
**Назначение:** Хранит неизменяемую историю версий каждого шаблона, метаданные загруженного файла, ссылку на файл в хранилище и результаты разбора из `template_parser.py`.

| Поле | Тип PostgreSQL | Обязательность | Ограничения и значения по умолчанию | Описание |
| :--- | :--- | :--- | :--- | :--- |
| `template_id` | `text` | `NOT NULL` (через `PK`) | `PK`, `FK -> templates(template_id)` | Идентификатор шаблона, к которому относится версия |
| `minor_version` | `int` | `NOT NULL` (через `PK`) | `PK`, `CHECK (minor_version >= 0)` | Целочисленный номер редакции (`0` для `1.0`, `1` для `1.1`, `10` для `1.10`) |
| `created_at` | `timestamptz` | `NOT NULL` | `DEFAULT current_timestamp` | Время сохранения данной версии в UTC |
| `title` | `text` | `NOT NULL` | — | Название шаблона на момент загрузки версии |
| `change_note` | `text` | `NULL` | — | Необязательный комментарий к изменениям |
| `file_name` | `text` | `NOT NULL` | — | Исходное имя загруженного файла (например, `Уведомление.ott`) |
| `file_format` | `varchar(3)` | `NOT NULL` | `CHECK (file_format IN ('odt', 'ott'))` | Формат файла, определённый парсером |
| `size_in_bytes` | `int` | `NOT NULL` | `CHECK (size_in_bytes BETWEEN 1 AND 20971520)` | Размер файла в байтах (не пустой, максимум 20 МиБ) |
| `file_sha256` | `varchar(64)` | `NOT NULL` | `CHECK (file_sha256 ~ '^[0-9A-Fa-f]{64}$')` | SHA-256 хеш содержимого файла (64 hex-символа) |
| `path_to_file` | `text` | `NOT NULL` | `UNIQUE` | Относительный путь к бинарному файлу в каталоге сервиса |
| `page_format` | `text` | `NOT NULL` | `DEFAULT 'A4'` | Формат страницы документа |
| `orientation` | `varchar(10)` | `NOT NULL` | `DEFAULT 'portrait'`, `CHECK (orientation IN ('portrait', 'landscape'))` | Ориентация страницы |
| `document_text` | `text` | `NOT NULL` | — | Полный извлечённый текст документа из парсера |
| `fields` | `jsonb` | `NOT NULL` | `DEFAULT '[]'::jsonb`, `CHECK (jsonb_typeof(fields) = 'array')` | JSON-массив описаний полей шаблона |

* **Первичный ключ:** составной ключ `PRIMARY KEY (template_id, minor_version)` — однозначно находит конкретную версию шаблона.
* **Внешние ключи:** `FOREIGN KEY (template_id) REFERENCES templates(template_id) ON DELETE RESTRICT` — связывает версию с родительским шаблоном и запрещает удаление шаблона, пока у него есть версии.
* **Ограничения уникальности:**
  1. `PRIMARY KEY (template_id, minor_version)` — исключает появление двух версий с одинаковым номером у одного шаблона.
  2. `UNIQUE (path_to_file)` — гарантирует, что разные версии никогда не перезапишут один и тот же файл на диске.
  

### 2.3. Индексы и их назначение

1. **`templates_pkey` (B-Tree по `templates.template_id`)** — создаётся автоматически для первичного ключа. Используется для быстрой проверки существования шаблона при `POST /api/v1/templates` и `GET /api/v1/templates/{template_id}`.
2. **`template_versions_pkey` (составной B-Tree по `template_versions(template_id, minor_version)`)** — создаётся автоматически для составного `PK`. Решает сразу три задачи:
   * точечный поиск версии по `template_id` и `minor_version`;
   * выборка истории всех версий шаблона по возрастанию или убыванию (`ORDER BY minor_version DESC`) без дополнительной сортировки в памяти;
   * быстрое нахождение актуальной версии (`MAX(minor_version)`).
3. **`template_versions_path_to_file_key` (уникальный B-Tree по `path_to_file`)** — создаётся автоматически для ограничения `UNIQUE`, гарантирует уникальность путей к файлам и не дает разным версиям шаблона ссылаться на один и тот же файл.
4. **`idx_templates_id_trgm` и `idx_template_versions_title_trgm` (GIN-индексы с `pg_trgm`)** — используются в `GET /api/v1/templates` для быстрого поиска по части строки без учета регистра (`ILIKE '%q%'`) по идентификатору шаблона и названию его актуальной версии.
